# Контроль качества денситометрии (DXA)

Локальный ИИ-сервис оценки DICOM поясничного отдела позвоночника и проксимального отдела бедра. Определяет область и сторону бедра, нарушения укладки, оси позвоночника, ротации, ROI и артефакты. Поддерживает пакетную загрузку, общий CSV, просмотр объяснений, дополнительные DICOM-серии и текстовые отчёты DICOM SR. Изображения обрабатываются локально, без внешних сервисов.

## Структура и требования

- `dxa_web_app/` — FastAPI, веб-интерфейс, инференс, CSV, визуализация и DICOM SR.
- `models/` — веса, алгоритм ROI, скрипты обучения и проверки моделей.
- `calculate_metrix/` — расчёт метрик и сохранённый отчёт.
- `Dockerfile`, `docker-run.sh` — контейнер и скрипт сборки/запуска для Linux/UNIX.
- `requirements.txt` — полный перечень зависимостей с фиксированными версиями.
- `uploads/` — данные и результаты; создаётся при запуске.

Среда: **Python 3.12.14**, образ **python:3.12.14-slim-bookworm**. Основные зависимости: PyTorch/torchvision, timm, scikit-learn, NumPy/SciPy, OpenCV, pydicom, pandas, FastAPI/Uvicorn, Jinja2. Версии — в `requirements.txt`. Для установки и сборки нужен интернет, для инференса — нет. Сохраните поставляемые веса `.pt`/`.pth` и `position_model/train.py` в структуре `models/`.

Оценочные требования для развёртывания (не подтверждены нагрузочными замерами):

| Ресурс | Минимум для пробного запуска | Рекомендуется |
|---|---|---|
| CPU | x86-64, 4 ядра | x86-64, 8 ядер |
| RAM | 2 ГБ | 8 ГБ |
| GPU | Не требуется | NVIDIA, 4 ГБ VRAM, совместимый драйвер CUDA |
| Свободный диск | 20 ГБ + место для данных | 40 ГБ + место для данных |

CUDA выбирается автоматически при доступности в PyTorch. Норматив ТЗ — не более 3 минут на исследование; выполнение норматива и воспроизводимость на целевом оборудовании требуют отдельных замеров.

## Запуск в контейнере

Команды выполняются из **`src/quality_of_densitometry`**, где лежит `Dockerfile` (или из корня отдельно склонированного репозитория).

**Linux / UNIX:** установите и запустите Docker Engine:

```sh
sh docker-run.sh
```

Скрипт собирает образ `dxa-quality:local`, запускает контейнер в фоне, выводит его ID и сохраняет данные в томе `dxa-uploads`. Альтернативные варианты:

```sh
PORT=8080 IMAGE=dxa-quality:local VOLUME=dxa-uploads sh docker-run.sh
# GPU: требуется NVIDIA Container Toolkit
GPUS=all sh docker-run.sh
```

Перед повторным использованием порта остановите предыдущий контейнер.

**Windows (PowerShell):** установите и запустите Docker Desktop с WSL 2 и Linux-контейнерами:

```powershell
docker build -t dxa-quality:local .
docker run -d --rm --init --name dxa-quality -p 8000:8000 --mount type=volume,src=dxa-uploads,dst=/app/uploads dxa-quality:local
```

При настроенной поддержке NVIDIA GPU в Docker Desktop добавьте `--gpus all` перед именем образа. Сборка проверяет загрузку всех шести компонентов анализа и прерывается при отсутствии или несовместимости весов.

Логи: `docker logs -f <ID>`. Остановка: `docker stop <ID>`; в Windows вместо `<ID>` можно указать `dxa-quality`. Том с данными сохраняется.

## Локальный запуск без Docker

Установите Python 3.12.14. Из того же каталога создайте окружение.

**Windows (PowerShell):**

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn dxa_web_app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

**Linux:**

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn dxa_web_app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

Проверьте сообщение о загрузке **6 моделей** (включая алгоритм ROI). Используйте один worker: задачи хранятся в памяти процесса. Остановка — `Ctrl+C`.

## Использование и форматы данных

Откройте **http://localhost:8000** (при смене порта замените `8000`). Загрузите один или несколько `.dcm`, `.dicom` либо ZIP с такими файлами во вложенных каталогах. Дождитесь анализа, скачайте CSV; откройте изображение для просмотра объяснений и экспорта.

Вход — однокадровые монохромные DICOM; по ТЗ исследование содержит до 3 изображений/серий. Персональные данные для классификации не нужны.

Выход — CSV в UTF-8 с BOM, разделитель — запятая, одна строка на изображение. Колонки по п. 2.5 ТЗ:

```text
path_to_study,study_uid,image_uid,anatomical_region,quality_class,violation_type,processing_status,time_of_processing
```

`path_to_study` — путь файла на сервере; UID — `StudyInstanceUID` и `SOPInstanceUID` (пустые при отсутствии). Класс **0** — качественное, **1** — есть нарушение; при `Failure` класс пустой. Нарушения перечислены через `;`. Статус — `Success`/`Failure`. Время в секундах включает метаданные и инференс, но не загрузку, распаковку и визуализацию.

Итоговое заключение API, интерфейса, CSV и DICOM SR использует единые категории:
позвоночник — укладка, ось, посторонние предметы; бедро — укладка и ROI.
Артефакты бедра остаются в `model_predictions.artifact` как дополнительное
наблюдение и не влияют на итоговый класс или его вероятность. CSV экспортирует
готовое заключение без пересчёта класса, включая результат ручной проверки.

## API

Интерактивная документация: **http://localhost:8000/docs**. `index` — индекс изображения в `results`, начиная с **0**.

| Метод и путь | Назначение |
|---|---|
| `POST /api/analyze` | Multipart: повторяемое поле `files` (также поддерживается `file`); ответ — `task_id` |
| `GET /api/status/{task_id}` | `status` (`PROCESSING`/`COMPLETED`), `progress`, `total`, `results`; причины ошибок — `error_message` |
| `GET /api/download/{task_id}` | Общий CSV после завершения |
| `GET /api/visualization/{task_id}/{index}` | Исходное изображение и объяснения в JSON |
| `GET /api/visualization/{task_id}/{index}/dicom` | ZIP дополнительной DICOM-серии изображения |
| `GET /api/series/{task_id}` | Общий ZIP дополнительных визуальных DICOM-серий пакета с `manifest.json` |
| `GET /api/dicom-sr/{task_id}/{index}` | DICOM SR изображения |
| `GET /api/dicom-sr/{task_id}` | ZIP отчётов DICOM SR пакета с `manifest.json` |
| `PUT /api/conclusion/{task_id}/{index}` | JSON `{"violations": [], "revision": 0}`; отмена/восстановление найденных нарушений |

### Примеры запросов

Сервис должен быть запущен. В примерах используется `http://localhost:8000`;
при другом адресе или порте замените его во всех командах. В Linux/macOS используйте
`curl`, в Windows PowerShell — `curl.exe` (чтобы не вызвать одноимённый псевдоним).
Пути после `@` указывают на локальные файлы клиента.

**Загрузка одного DICOM:**

```sh
curl -sS -F "files=@study.dcm" http://localhost:8000/api/analyze
```

**Пакет из нескольких файлов и архива:** повторяйте поле `files`.

```sh
curl -sS -F "files=@spine.dcm" -F "files=@hip.dicom" -F "files=@batch.zip" http://localhost:8000/api/analyze
```

Пример ответа (ID будет другим):

```json
{"task_id":"8b7f620e-701c-45f9-8c77-e31435876139"}
```

**Статус и результаты:** замените `TASK_ID` полученным ID.

```sh
curl -sS http://localhost:8000/api/status/TASK_ID
```

Повторяйте запрос до `status: "COMPLETED"`. Поля `progress` и `total` показывают
число обработанных и найденных файлов; `results` содержит результаты изображений.
`COMPLETED` означает завершение пакета, а не успех каждой строки: проверьте
`processing_status` и `error_message` у каждого результата.

**Общий CSV после завершения:**

```sh
curl -sS -o results.csv http://localhost:8000/api/download/TASK_ID
```

**Визуализация первого изображения:** `0` — индекс в массиве `results`.

```sh
curl -sS -f -o visualization_0.json http://localhost:8000/api/visualization/TASK_ID/0
curl -sS -f -o visualization_0.zip http://localhost:8000/api/visualization/TASK_ID/0/dicom
```

JSON содержит `original` (PNG в data URL), `items` с изображениями и пояснениями,
а также `warnings`. ZIP содержит дополнительную DICOM-серию. Если серии нет,
запрос ZIP вернёт HTTP 409; это возможно и для успешно обработанного снимка.

**Все дополнительные визуальные серии пакета:**

```sh
curl -sS -f -o visualization_series.zip http://localhost:8000/api/series/TASK_ID
```

Архив содержит отдельные каталоги изображений и `manifest.json` со статусом
экспорта каждой строки (`Success`, `Partial`, `Skipped`, `Failure`), списком файлов,
предупреждениями и причинами ошибок. Ошибка одного снимка не отменяет остальные.
Если серий нет, архив содержит только манифест.

**Текстовый DICOM SR одного изображения и всех изображений пакета:**

```sh
curl -sS -f -o report_0.dcm http://localhost:8000/api/dicom-sr/TASK_ID/0
curl -sS -f -o dicom_sr_reports.zip http://localhost:8000/api/dicom-sr/TASK_ID
```

Скачивайте после `COMPLETED`. Общий ZIP включает `manifest.json`: проверьте его,
чтобы узнать, для каких изображений отчёт не сформирован.

**Ручная отмена нарушений первого изображения:** создайте файл `conclusion.json`
в UTF-8 со следующим содержимым:

```json
{"violations": [], "revision": 0}
```

Перед отправкой получите актуальный статус задачи. В `revision` укажите
`results[0].review_revision`; если поле отсутствует, используйте `0`.
Пустой `violations` отменяет все нарушения этого изображения:

```sh
curl -sS -f -X PUT -H "Content-Type: application/json" --data-binary "@conclusion.json" http://localhost:8000/api/conclusion/TASK_ID/0
```

Ответ содержит обновлённый результат и увеличенный `review_revision`.
Для частичной отмены оставьте в `violations` нужные строки из исходного заключения.
Для восстановления возьмите список `model_conclusion.violation_type` из актуального
результата и отправьте его с текущей ревизией. Новые нарушения, которых модель
не находила, добавлять нельзя. При HTTP 409 заново получите статус и проверьте
ревизию, завершение пакета и успешность анализа изображения. После изменения
заключения повторно скачайте CSV или SR, чтобы получить актуальный отчёт.




## Модели и обработка

1. **Область:** EfficientNet-B0, классы `spine`, `hip_right`, `hip_left`; min-max, дополнение до квадрата, 224×224.
2. **Позвоночник:** ансамбль по геометрическим/CNN-признакам для оси; ResNet18 для укладки (min-max, учёт MONOCHROME1, 256×256, ImageNet-нормализация).
3. **Бедро:** EfficientNet-B0 с признаком стороны, оценки ротации/укладки и ROI; min-max, квадрат, обычно 384×384, нормализация `(x − 0.5) / 0.25`.
4. **Артефакты:** ResNet18; отсечение по 1–99 перцентилям, CLAHE, 384×384, ImageNet-нормализация.
5. **Отступы ROI бедра:** геометрический алгоритм без весов, пороги 30 мм сверху/снизу и 20 мм снаружи.

Постобработка применяет пороги из весов, объединяет нарушения и присваивает класс 1 при наличии хотя бы одного. Объяснения строятся по запросу (тепловые карты, ось, ключевые точки); исходный DICOM не изменяется. Пересмотр заключения влияет на отчёты, сохраняя исходные предсказания и пометки.

## Ограничения и известные ошибки

- ROI — эвристика под масштаб X=0.6, Y=1.05 мм. Несовместимый `PixelSpacing` или противоречие стороны дают `Failure`; пограничные отступы — класс 1 с предупреждением. Точность требует независимой валидации.
- Повреждённый DICOM, ошибка декодирования или модели дают строку `Failure`, остальные файлы продолжают обрабатываться. Проверьте `error_message`, исходник, кодек и загрузку весов. Повреждённый ZIP или архив без DICOM даёт отдельную строку ошибки.
- Базовые маршруты могут вернуть JSON `error` с HTTP 200. Экспорт и пересмотр используют также HTTP 404/409/422: проверьте ID, завершение задачи и актуальную `revision`. Ошибки пакетного экспорта SR записываются в `manifest.json`.
- После перезапуска задачи и правки заключений теряются, даже если файлы остались в томе: загрузите данные повторно.
- Отдельного определения проекции и автоматической коррекции разметки нет. Карты объяснений не являются валидированной сегментацией. Другие области, цветные и многокадровые DICOM не заявлены.
