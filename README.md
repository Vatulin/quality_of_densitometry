зависимости при необходимости:
```
pip install fastapi uvicorn python-multipart pandas pydicom torch torchvision jinja2 pillow
```

запуск сервера из папки `dxa_web_app`:
```
uvicorn main:app --reload
```

В интерфейсе можно выбрать или перетащить несколько `.dcm`, `.dicom` и `.zip`
одновременно. Они обрабатываются одной задачей с общим отчётом CSV.
Файлы с одинаковыми именами сохраняются в отдельных каталогах.

API: `POST /api/analyze` принимает несколько multipart-полей `files`.
Прежнее поле `file` для одного файла также поддерживается.
Ответ содержит `task_id`; статус и результаты доступны через
`GET /api/status/{task_id}`, отчёт — `GET /api/download/{task_id}`.

CSV в UTF-8 с BOM содержит колонки из п. 2.5 ТЗ в указанном порядке:
`path_to_study`, `study_uid`, `image_uid`, `anatomical_region`, `quality_class`,
`violation_type`, `processing_status`, `time_of_processing`.
Дополнительная колонка `error_message` содержит причину технической ошибки.
Путь указывает на сохранённый файл на сервере, UID берутся из DICOM-тегов
StudyInstanceUID и SOPInstanceUID (при отсутствии остаются пустыми).
Время измеряется в секундах для каждого изображения, включая чтение его метаданных
и инференс, без времени загрузки и распаковки архива.
Класс качества — целое `0` или `1`; при `Failure` класс остаётся пустым.
Сбой отдельного файла не останавливает пакет. Повреждённый ZIP или ZIP без
DICOM-файлов отражается отдельной строкой `Failure` с путём к архиву.

Проверка отступов ROI бедра в веб-сервисе и `position_model/test.py` использует
общую функцию `analyze_roi` из `models/position_model/train.py`. Проверяются
30 мм сверху, 30 мм снизу и 20 мм с наружной стороны; сторона передаётся
из классификатора области. Измерения доступны в ответе API:
`results[].model_predictions.position.roi_details`.
Пограничные измерения дают `Success` с классом `1` (возможный дефект ROI),
описанием пограничного отступа и предупреждением в деталях результата.
Противоречие стороны геометрии даёт `Failure`.
Алгоритм эвристический, рассчитан на исходный масштаб X=0.6, Y=1.05 мм;
несовместимый PixelSpacing отклоняется. Требуется независимая валидация точности.

В `dxa_web_app/main.py` находятся API, сбор результатов и экспорт;
классы моделей и адаптер ROI вынесены в `dxa_web_app/inference_models.py`.

### Интерактивные исследования и дополнительные серии

После анализа нажмите на имя файла в таблице. Карточка исследования показывает
исходный DICOM, найденные нарушения и отдельный слой для каждого объяснения.
Можно переключать слои, скрывать пометки, изменять их прозрачность, увеличивать
изображение и скачивать текущий вид в PNG. Возврат к списку сохраняет результаты пакета.

Способы визуализации:
- артефакты, укладка позвоночника и нарушения бедра: Grad-CAM выбранного
  положительного класса с той же предобработкой, что при классификации;
- ось позвоночника: окклюзионная карта 6×6 по снижению оценки ансамбля;
- ROI бедра: ключевые точки, линии недостаточных отступов с величинами в мм
  или рамка фрагмента, пересечённого нижней границей снимка.

Карты пересчитываются в координаты исходного изображения, включая снятие
квадратного паддинга моделей бедра и оси позвоночника. Это объяснения решения
классификатора, а не валидированная сегментация границ дефекта. Если карта не
получена, причина видна в карточке; фиктивные пометки не создаются. При норме
или ошибке анализа доступен только исходный снимок (если его можно прочитать).
Поддерживается однокадровый монохромный DICOM, включая MONOCHROME1.

Новые маршруты:
- `GET /studies/{task_id}/{study_id}` — карточка исследования;
- `GET /api/studies/{task_id}/{study_id}` — результат, PNG исходника и прозрачные
  слои в data URL, методы и предупреждения;
- `GET /api/series/{task_id}` — ZIP всего пакета: исходные PNG, PNG с пометками,
  DICOM Secondary Capture, `annotations.json` и общий `manifest.json`.

`study_id` возвращается в каждой строке `/api/status/{task_id}`. Для каждого
исходного изображения с пометками создаётся отдельная SeriesInstanceUID;
каждый слой — отдельный SOPInstanceUID, с сохранением StudyInstanceUID и
ссылкой SourceImageSequence на исходник. Исходный DICOM не изменяется.
PNG сохраняет текущую прозрачность в просмотрщике; ZIP содержит все слои
по отдельности с фиксированной прозрачностью. При отсутствии пометок ZIP
содержит исходный PNG и сведения о причине, без пустой DICOM-серии.

Объяснения строятся локально при первом открытии или экспорте и кэшируются
в `uploads/{task_id}/visualizations`. Этот этап не входит во время исходной
классификации в CSV. Доступ к общим моделям сериализован, чтобы Grad-CAM-хуки
не пересекались с другими запросами. Список задач, как и раньше, хранится в
памяти: после перезапуска сервера необходимо загрузить исследования заново.

Проверки из корня проекта: `python -m unittest dxa_web_app.test_visualization -v`.
